# 01 · 产品需求说明（PRD）

> 版本：v0.3（原型阶段） · 更新：2026-11-16
> 试点学校：**青岛理工职业学院**

## 1. 产品定位

面向在校大学生的 **校园综合服务平台**，以微信小程序为最终形态。由两大板块组成：

| 板块 | 作用 | 盈利 |
|---|---|---|
| ① 校园基础业务（跑腿、代取快递、二手、树洞） | 高频刚需、做日活、拉新留存 | 小额抽成：跑腿赏金 5%、二手成交价 2%（"不抽多，积少成多"，后台可调） |
| ② 周边本地生活（餐饮、外卖、网吧、台球、民宿……） | 变现主力 | 商品差价（平台 + 客户经理分成）、配送费结余、首页推荐位广告 |
| ③ 学校百事通（AI 问答，预留） | 新生入学咨询、平台使用答疑，培养"有事先问平台"的习惯 | 公益性质，盈利后接入 |

**核心卖点：全平台低价。** 平台不收高额抽佣，省下的钱分给学生和平台，每个商品都明确标注"比其他平台省 X 元"。大学生对价格敏感，便宜一两块就会形成习惯。

> 学生端文案不直接点名竞品（客户反馈）：标语默认「全平台低价」、比价对象称「其他平台」，均可在后台「平台参数」修改。按《广告法》不使用"最低价""全网最低"等绝对化用语。

## 2. 用户角色

| 角色 | 说明 | 原型 |
|---|---|---|
| 学生（用户端） | 选择学校后使用全部 C 端功能 | ✅ v0.1 |
| 商家 | 学校周边商户，入驻后上架团购/外卖、核销券码、看结算 | ✅ v0.1 |
| 客户经理（地推/BD） | 拥有专属邀请码，邀请商家入驻并绑定，享受推广商家订单的分成 | ✅ v0.1 |
| 骑手 | 校园外卖团队成员（学生兼职，申请后平台审核），按批次集中取餐送达，按单提成 | ✅ v0.2 |
| 平台管理员 | 学校开通、商家终审、商品比价抽查、用户与团队、分成参数、知识库、树洞审核 | ✅ v0.2（PC 后台） |

## 3. 多学校入驻

- 首次进入选择学校，可随时切换（商家账号绑定入驻学校，不可切换）。
- 学校状态：`active` 已开通 / `preparing` 筹备中（列表可见不可选）/ `applying` 用户申请中（列表不可见）。
- 列表底部「申请开通我的学校」：用户提交学校名、城市、联系方式 → 平台评估后开通。
- **所有内容按学校隔离**：跑腿、二手、树洞、商家都归属某个学校，用户只看到当前学校的数据。
- 每个学校独立配置：外卖送餐时间点（如 11:30 / 17:30 / 21:00）、校内取餐点。

## 4. 板块一：校园基础业务

### 4.1 跑腿 / 代取快递
- 发布：类型（跑腿 / 代取快递）、标题、说明、取件地点、送达地点、赏金（1~200 元）。
- 代取快递额外字段：快递驿站、取件码、包裹大小。**取件码只有发布者和接单人可见**。
- 状态流转：`待接单 → 已接单 → 已送达 → 已完成`；未接单前发布者可取消（托管赏金原路退回）。
- 不能接自己的单；并发抢单以数据库条件更新保证只有一人成功。
- **赏金托管（v0.3）**：发布时预付赏金（原型为模拟支付），发布者确认完成后打给接单人，平台从赏金中抽 `errand_fee_rate`（默认 5%）服务费，例：赏金 ¥3 → 接单人到手 ¥2.85。
- **拍照留证（v0.3，客户反馈）**：接单人点「拍照确认送达」必须上传照片，发布者在订单详情查看送达凭证。

### 4.2 二手交易
- 发布：标题、描述、分类（教材/数码/生活/运动/其他）、成色、价格、原价、联系方式。
- 列表按分类筛选、关键词搜索；详情记录浏览量。
- **担保交易（v0.3）**：买家点「我想要」付款由平台托管 → 宝贝锁定为"交易中"、买家可见卖家联系方式 → 当面验货 → 买家「确认收货」后货款打给卖家，平台抽 `market_fee_rate`（默认 2%）；交易前任一方可取消，全额退款。
- 卖家联系方式下单后才可见，引导走担保交易；卖家也可标记"已线下售出 / 下架"。
- 「我的二手交易」：我买到的 / 我卖出的。
- 后续：站内私信、毕业季专场。

### 4.3 树洞
- 匿名发帖：系统随机生成匿名昵称（如"熬夜的水豚"），标签：日常/表白/吐槽/求助/失物招领。
- 点赞（可取消）、评论；同一帖子内同一用户匿名身份固定，楼主显示"洞主"。
- **前台匿名，后台实名留存**（满足《互联网跟帖评论服务管理规定》等要求，便于违规追溯）。
- 举报：原因（人身攻击/色情低俗/广告引流/虚假信息/泄露隐私/其他），同一用户对同一帖限一次；**累计 3 次自动隐藏**，后台复核（隐藏或驳回举报恢复）。
- 原型内置敏感词拦截；正式版接入微信内容安全接口 `msgSecCheck` + 人工复审。

## 5. 板块二：周边本地生活

### 5.1 商家入驻（客户经理推广绑定）
1. 客户经理线下拜访商家，给出 **专属邀请码**（如 `QD8801`）。
2. 商家在小程序「我的 → 商家入驻」填写店铺信息 + 邀请码提交。
3. 系统把商家与客户经理 **永久绑定**（`merchants.manager_id`），此后该商家所有订单的差价按比例分给该客户经理。
4. 审核：v0.1 由绑定的客户经理初审即生效；v0.2 增加平台终审。无邀请码的商家进入平台公海，由管理员审核。

### 5.2 商品与定价（核心，详见 [02-商业模式与定价分账](02-商业模式与定价分账.md)）
商家录入商品时必须填写 **竞品平台价**（同一商品在美团的实际售价），系统根据定价模式实时试算：用户实付、比美团省多少、商家到手、平台与客户经理各得多少。**不满足"至少比竞品便宜 1 元"的定价无法上架。**

商品类型：
- **团购套餐 / 代金券**（到店消费）：支付后生成 12 位券码，到店由商家核销。
- **校园外卖**（需商家开通外卖）：按学校固定送餐时间点集中配送到取餐点。

### 5.3 校园外卖团队
- 固定时间点配送（例：11:30 午餐、17:30 晚餐、21:00 夜宵），送餐前 40 分钟截单，错过自动顺延到次日同一时间点。
- 集中配送到校内取餐点（东门取餐柜、宿舍楼下等），一个骑手一趟送多单，成本远低于即时配送。
- 用户支付配送费（默认 1.5 元，远低于外卖平台），骑手每单提成（默认 1 元），结余归平台。
- 商家端按"日期 + 时间点"汇总备餐量，出餐后点「已出餐」。
- **流程**：学生下单支付 → 商家出餐（ready）→ 骑手按批次到店批量取餐（delivering）→ 按取餐点批量送达（completed，写入分账，骑手提成实时入账）。
- 骑手是学生的兼职身份：「我的 → 加入校园外卖团队」申请，后台审核通过后出现「骑手工作台」；取餐前只能看到同学脱敏手机号。
- 已出餐的外卖不可退款。

### 5.4 品类规划
餐饮（到店/外卖）、奶茶饮品、网吧、台球、KTV、民宿、理发、打印店、驾校等。v0.1 演示数据覆盖：餐饮、奶茶、网吧、台球、民宿。

### 5.4.1 首页推荐与推荐位（v0.3，客户反馈）
- 首页「热门推荐」分行业 tab（全部 / 美食 / 校园外卖 / 网吧 / 台球 / 民宿 / KTV），周边商家列表同规则：
  **每个行业前 3 位为推荐位（商家购买广告，手动置顶），其余按销量排序**。
- 商家端「首页推荐位」：查看本行业 3 个位置的占用与可投放日期，选商品 + 开始日期 + 天数，模拟支付后提交平台审核；驳回全额退款。
- 价格按天计费，默认第 1/2/3 位 ¥15 / ¥10 / ¥8，后台可调；后台也可直接排期（线下谈成的广告）。
- 依据《互联网广告管理办法》，推荐位在学生端标注"广告"。

### 5.4.2 福利群与领券中心（v0.3，客户反馈）
- 运营建企业微信福利群，每天在群里提醒抢券；首页「进群领福利」banner、「今日福利」券条、「领券中心」入口。
- 平台优惠券由后台配置：抵扣金额、门槛、范围（通用 / 外卖 / 到店团购）、每日发放数量、每日开抢时间、有效天数；每人每券每天限领 1 张。
- 下单页自动选中抵扣最多的可用券，可手动更换或不用；取消 / 退款时券退回。
- **优惠券由平台出资**：抵扣金额从平台收入中扣除，不影响商家到手与客户经理佣金。

### 5.5 订单与售后
- 团购：未核销券码随时可退（退款原路返回，库存回补）；已有核销的订单暂不支持部分退款（v0.2 支持按张退）。
- 外卖：商家未出餐前可退。
- "我的订单"展示累计已省金额（比价差额 + 优惠券），强化"用这个平台省钱"的心智。
- 订单详情参考美团：顶部大字状态 + 进度，「申请退款 / 联系商家 / 再来一单」为右对齐的小号描边按钮，退款不再是底部大按钮（客户反馈）。
- 校园外卖送达时骑手须在取餐点拍照，学生在订单详情可查看送达照片。

## 6. 学校百事通（AI 问答，预留）

- 入口：首页「学校百事通」卡片、「我的 → 学校百事通 · 帮助中心」。
- **当前**：本地 FAQ 知识库匹配（关键词 + 文本相似度），覆盖新生报到、校园卡、快递点、平台使用、退款等。未命中时引导去树洞求助。
- **接入后**：配置 `server/config.php` 的 `ai.enabled / endpoint / api_key / model`（OpenAI 兼容协议）即可，命中的 FAQ 作为上下文喂给模型，减少胡编；所有问答记录在 `ai_logs`，用于补充知识库。
- 知识库按学校区分，运营可维护本校专属问答。

## 7. 合规与风险提示（上线前必须处理）

| 事项 | 说明 | 建议 |
|---|---|---|
| **资金"二清"** | 平台先收全款再结算给商家，属于无证"二次清算"，有监管风险 | 正式上线使用 **微信支付服务商 + 分账**（或收付通），资金直接从微信分给商家、客户经理、平台 |
| **广告用语** | 《广告法》禁止"全网最低价""最便宜"等绝对化用语 | 对外宣传用"比美团省 X 元"（可举证的具体比价），不写"全网最低" |
| **比价真实性** | 竞品价须真实可查 | 客户经理录入时截图留档，平台定期抽查 |
| **树洞内容** | UGC 需要内容审核与实名追溯 | 接入 msgSecCheck、举报、后台审核；小程序类目需选"社交-社区/论坛"并具备相应资质 |
| **跑腿/二手纠纷** | 物品丢失、交易欺诈 | 用户协议免责条款、信用分、黑名单、平台托管赏金 |
| **食品安全** | 外卖团队涉及食品配送 | 商家须有食品经营许可证（入驻时上传），保温箱、骑手健康证 |
| **个人信息** | 手机号、取件码属于个人信息 | 最小化展示（已做脱敏与可见范围控制），隐私政策 |
| **小程序资质** | 涉及团购、外卖需企业主体 | 以公司主体注册小程序，申请对应服务类目 |

## 8. 版本范围

- **v0.1 原型**：学生端 + 商家端 + 客户经理端核心流程，Web 端 9:16 手机框预览，模拟支付。✅
- **v0.2 原型**：骑手端（批次取送）、平台管理后台、图片上传、树洞举报。✅
- **v0.3 原型（当前）**：客户反馈优化——推荐位广告、福利群领券、跑腿托管 + 抽成、二手担保交易 + 抽成、送达拍照、收益分配看板、学校百事通、视觉全面升级（Lucide 线性图标、统一设计规范）。✅
- **v0.4**：微信登录、站内私信、商家结算打款与提现、消息通知。
- **v1.0**：微信小程序正式版 + 微信支付分账，试点学校上线。
