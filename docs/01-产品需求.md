# 01 · 产品需求说明（PRD）

> 版本：v0.1（原型阶段） · 更新：2026-11-15
> 试点学校：**青岛理工职业学院**

## 1. 产品定位

面向在校大学生的 **校园综合服务平台**，以微信小程序为最终形态。由两大板块组成：

| 板块 | 作用 | 盈利 |
|---|---|---|
| ① 校园基础业务（跑腿、代取快递、二手、树洞） | 高频刚需、做日活、拉新留存 | 前期免费，后期可做跑腿抽成、置顶推广 |
| ② 周边本地生活（餐饮、外卖、网吧、台球、民宿……） | 变现主力 | 商品差价（平台 + 客户经理分成）、配送费结余 |
| ③ AI 自助问答（预留） | 新生入学咨询、平台使用答疑，培养"有事先问平台"的习惯 | 公益性质，盈利后接入 |

**核心卖点：比美团便宜。** 平台不收高额抽佣，省下的钱分给学生和平台，每个商品都明确标注"比美团省 X 元"。大学生对价格敏感，便宜一两块就会形成习惯。

## 2. 用户角色

| 角色 | 说明 | 原型 |
|---|---|---|
| 学生（用户端） | 选择学校后使用全部 C 端功能 | ✅ v0.1 |
| 商家 | 学校周边商户，入驻后上架团购/外卖、核销券码、看结算 | ✅ v0.1 |
| 客户经理（地推/BD） | 拥有专属邀请码，邀请商家入驻并绑定，享受推广商家订单的分成 | ✅ v0.1 |
| 骑手 | 校园外卖团队成员，按固定时间点集中配送，按单提成 | ⏳ v0.3（v0.1 由商家端代为推进配送状态） |
| 平台管理员 | 学校开通、商家终审、定价规则、结算打款、内容审核 | ⏳ v0.2 |

## 3. 多学校入驻

- 首次进入选择学校，可随时切换（商家账号绑定入驻学校，不可切换）。
- 学校状态：`active` 已开通 / `preparing` 筹备中（列表可见不可选）/ `applying` 用户申请中（列表不可见）。
- 列表底部「申请开通我的学校」：用户提交学校名、城市、联系方式 → 平台评估后开通。
- **所有内容按学校隔离**：跑腿、二手、树洞、商家都归属某个学校，用户只看到当前学校的数据。
- 每个学校独立配置：外卖送餐时间点（如 11:30 / 17:30 / 21:00）、校内取餐点。

## 4. 板块一：校园基础业务

### 4.1 跑腿 / 代取快递
- 发布：类型（跑腿 / 代取快递）、标题、说明、取件地点、送达地点、赏金（1~200 元）。
- 代取快递额外字段：快递驿站、取件码、包裹大小。**取件码只有发布者和接单人可见**。
- 状态流转：`待接单 → 已接单 → 已送达 → 已完成`；未接单前发布者可取消。
- 不能接自己的单；并发抢单以数据库条件更新保证只有一人成功。
- v0.1 赏金线下结算；v0.2 起改为下单预付托管，完成后打给接单人（平台可抽 0~10%）。

### 4.2 二手交易
- 发布：标题、描述、分类（教材/数码/生活/运动/其他）、成色、价格、原价、联系方式。
- 列表按分类筛选、关键词搜索；详情记录浏览量。
- 卖家可标记：在售 / 已预订 / 已售出 / 下架。
- v0.2：站内私信、图片上传、毕业季专场。

### 4.3 树洞
- 匿名发帖：系统随机生成匿名昵称（如"熬夜的水豚"），标签：日常/表白/吐槽/求助/失物招领。
- 点赞（可取消）、评论；同一帖子内同一用户匿名身份固定，楼主显示"洞主"。
- **前台匿名，后台实名留存**（满足《互联网跟帖评论服务管理规定》等要求，便于违规追溯）。
- 原型内置敏感词拦截；正式版接入微信内容安全接口 `msgSecCheck` + 人工复审 + 举报。

## 5. 板块二：周边本地生活

### 5.1 商家入驻（客户经理推广绑定）
1. 客户经理线下拜访商家，给出 **专属邀请码**（如 `QD8801`）。
2. 商家在小程序「我的 → 商家入驻」填写店铺信息 + 邀请码提交。
3. 系统把商家与客户经理 **永久绑定**（`merchants.manager_id`），此后该商家所有订单的差价按比例分给该客户经理。
4. 审核：v0.1 由绑定的客户经理初审即生效；v0.2 增加平台终审。无邀请码的商家进入平台公海，由管理员审核。

### 5.2 商品与定价（核心，详见 [02-商业模式与定价分账](02-商业模式与定价分账.md)）
商家录入商品时必须填写 **竞品平台价**（同一商品在美团的实际售价），系统根据定价模式实时试算：用户实付、比美团省多少、商家到手、平台与客户经理各得多少。**不满足"至少比竞品便宜 1 元"的定价无法上架。**

商品类型：
- **团购套餐 / 代金券**（到店消费）：支付后生成 12 位券码，到店由商家核销。
- **校园外卖**（需商家开通外卖）：按学校固定送餐时间点集中配送到取餐点。

### 5.3 校园外卖团队
- 固定时间点配送（例：11:30 午餐、17:30 晚餐、21:00 夜宵），送餐前 40 分钟截单，错过自动顺延到次日同一时间点。
- 集中配送到校内取餐点（东门取餐柜、宿舍楼下等），一个骑手一趟送多单，成本远低于即时配送。
- 用户支付配送费（默认 1.5 元，远低于外卖平台），骑手每单提成（默认 1 元），结余归平台。
- 商家端按"日期 + 时间点"汇总备餐量。

### 5.4 品类规划
餐饮（到店/外卖）、奶茶饮品、网吧、台球、KTV、民宿、理发、打印店、驾校等。v0.1 演示数据覆盖：餐饮、奶茶、网吧、台球、民宿。

### 5.5 订单与售后
- 团购：未核销券码随时可退（退款原路返回，库存回补）；已有核销的订单暂不支持部分退款（v0.2 支持按张退）。
- 外卖：商家未出餐前可退。
- "我的订单"展示累计已省金额，强化"用这个平台省钱"的心智。

## 6. AI 自助问答（预留）

- 入口：首页「问一问」。
- **当前**：本地 FAQ 知识库匹配（关键词 + 文本相似度），覆盖新生报到、校园卡、快递点、平台使用、退款等。未命中时引导去树洞求助。
- **接入后**：配置 `server/config.php` 的 `ai.enabled / endpoint / api_key / model`（OpenAI 兼容协议）即可，命中的 FAQ 作为上下文喂给模型，减少胡编；所有问答记录在 `ai_logs`，用于补充知识库。
- 知识库按学校区分，运营可维护本校专属问答。

## 7. 合规与风险提示（上线前必须处理）

| 事项 | 说明 | 建议 |
|---|---|---|
| **资金"二清"** | 平台先收全款再结算给商家，属于无证"二次清算"，有监管风险 | 正式上线使用 **微信支付服务商 + 分账**（或收付通），资金直接从微信分给商家、客户经理、平台 |
| **广告用语** | 《广告法》禁止"全网最低价""最便宜"等绝对化用语 | 对外宣传用"比美团省 X 元"（可举证的具体比价），不写"全网最低" |
| **比价真实性** | 竞品价须真实可查 | 客户经理录入时截图留档，平台定期抽查 |
| **树洞内容** | UGC 需要内容审核与实名追溯 | 接入 msgSecCheck、举报、后台审核；小程序类目需选"社交-社区/论坛"并具备相应资质 |
| **跑腿/二手纠纷** | 物品丢失、交易欺诈 | 用户协议免责条款、信用分、黑名单、平台托管赏金 |
| **食品安全** | 外卖团队涉及食品配送 | 商家须有食品经营许可证（入驻时上传），保温箱、骑手健康证 |
| **个人信息** | 手机号、取件码属于个人信息 | 最小化展示（已做脱敏与可见范围控制），隐私政策 |
| **小程序资质** | 涉及团购、外卖需企业主体 | 以公司主体注册小程序，申请对应服务类目 |

## 8. 版本范围

- **v0.1 原型（当前）**：学生端 + 商家端 + 客户经理端核心流程，Web 端 9:16 手机框预览，模拟支付。
- **v0.2**：平台管理后台、图片上传、真实短信/微信登录、跑腿赏金托管。
- **v0.3**：骑手端、配送批次调度、商家结算打款。
- **v1.0**：微信小程序正式版 + 微信支付分账，试点学校上线。
