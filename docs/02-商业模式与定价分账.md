# 02 · 商业模式与定价分账

> 实现代码：`server/src/Services/PricingService.php`（定价试算）、`server/src/Services/OrderService.php`（订单快照与分账流水）
> 所有金额在系统内以 **分** 为单位存储和计算，避免浮点误差。

## 1. 基本思路

学生在美团买一份 15 元的黄焖鸡，美团扣除抽佣、推广费后，商家实际到手约 15 × 0.7 = **10.5 元**，中间 4.5 元被平台拿走。

我们直接对接商家，把这 4.5 元的空间拆成三份：**学生省钱 + 平台收入 + 客户经理佣金**，商家到手不变甚至量更大。

## 2. 两种定价模式

### 模式一：代金券模式（voucher）· 商家到手不变

适合：不愿让利、只想多一个渠道的商家。

| 项目 | 公式 | 示例 |
|---|---|---|
| 竞品价 | 美团用户实付 | 15.00 |
| 商家到手价 | 商家在美团的到手 | 10.50 |
| 代金券 | 平台卖"1 元抵 2 元"券 | 券面额 2，券售价 1 |
| 到店标价 | 到手价 + 券面额 | **12.50** |
| 用户实付 | 到手价 + 券售价 | **11.50**（比美团省 3.50） |
| 商家得 | 到手价 | 10.50 |
| 差价毛利 | 用户实付 − 商家到手 = 券售价 | 1.00 |
| 客户经理佣金 | 毛利 × 经理分成比例（默认 50%） | 0.50 |
| 平台留存 | 毛利 − 佣金 | 0.50 |

### 模式二：平台定价模式（fixed）· 压缩商家利润换销量

适合：愿意以更低到手价换取稳定学生客流的商家（课间、周末集中消费）。

| 项目 | 示例 |
|---|---|
| 竞品价 | 15.00 |
| 约定商家到手价 | **9.50**（平台与商家谈定） |
| 平台售价（用户实付） | 12.00（比美团省 3.00） |
| 差价毛利 | 2.50 |
| 客户经理佣金（50%） | 1.25 |
| 平台留存 | 1.25 |

## 3. 定价校验规则（不满足无法上架）

1. `0 < 商家到手价 < 竞品价`
2. 代金券模式：`0 < 券售价 < 券面额`
3. 平台定价模式：`商家到手价 ≤ 平台售价`
4. **`竞品价 − 用户实付 ≥ min_saving`**（默认 1 元），保证"永远比美团便宜"
5. 佣金 = `floor(毛利 × manager_rate)`，向下取整到分，余数归平台
6. 商家未绑定客户经理时，毛利全部归平台

商家/客户经理录入商品时，前端调用 `POST /api/merchant/quote` 实时展示试算结果。

## 4. 校园外卖的配送费

| 项目 | 默认值 | 说明 |
|---|---|---|
| 配送费（用户付） | 1.50 / 单 | 远低于外卖平台 |
| 骑手提成 | 1.00 / 单 | 固定时间点集中配送，一趟多单，骑手收入可观 |
| 配送结余（平台） | 0.50 / 单 | 覆盖保温箱、取餐柜等成本 |

外卖订单平台净收入 = 商品差价 − 经理佣金 + 配送费 − 骑手提成。

## 5. 可调参数（`settings` 表）

| key | 默认 | 含义 |
|---|---|---|
| `manager_rate` | 0.5 | 客户经理在差价毛利中的分成比例 |
| `min_saving` | 100（分） | 用户实付至少比竞品便宜多少 |
| `delivery_fee` | 150（分） | 外卖配送费 |
| `rider_commission` | 100（分） | 骑手每单提成 |
| `takeout_cutoff_minutes` | 40 | 送餐前多少分钟截单 |
| `merchant_auto_approve` | false | 商家入驻是否免审 |

> 后续可扩展：按学校/品类/客户经理等级设置不同分成比例；新商家首月平台让利；学生拉新奖励。

## 6. 订单快照与分账流水

- **下单时固化快照**：订单表记录 `merchant_amount / platform_gross / manager_commission / rider_commission / platform_net`，之后修改定价或分成比例不影响历史订单。
- 快照金额 = 单份金额 × 数量，因此可以按张精确拆分。
- **结算时写流水（ledger）**：
  - 团购：**每核销一张券** 写一组流水（商家结算 / 经理佣金 / 平台差价）。
  - 外卖：**送达时** 写流水，额外写骑手提成和配送费结余。
- 流水是商家结算、客户经理佣金发放、平台对账的唯一依据。

## 7. 资金合规（上线前）

原型阶段为模拟支付。正式版 **不能由平台先收全款再转给商家**（"二清"风险），应采用：

- **微信支付服务商模式 + 分账**：商家作为特约商户进件，用户付款直接进商家账户，支付成功后按订单快照发起分账：平台 + 客户经理（个人分账接收方）。
- 分账比例上限需符合微信规则（一般 ≤ 30%），本模型的差价比例远低于此。

## 8. 单位经济测算（示例）

假设试点学校日均 300 单团购/外卖，客单价 13 元，平均差价 1.5 元：

| 指标 | 日 | 月（30 天） |
|---|---|---|
| GMV | 3,900 | 117,000 |
| 差价毛利 | 450 | 13,500 |
| 客户经理佣金（50%） | 225 | 6,750 |
| 平台留存 | 225 | 6,750 |
| 外卖配送结余（按 100 单 × 0.5） | 50 | 1,500 |

> 数据仅为模型演示，实际以试点运营数据为准。
