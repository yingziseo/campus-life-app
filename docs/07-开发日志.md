## 2026-11-15 · v0.1 项目初始化 + 后端核心

**完成**
- 与产品方对齐：PHP + SQLite 原型；最终形态为微信小程序；原型先做学生端、商家端、客户经理端，平台后台放到 v0.2；Web 端 9:16 手机框预览；GitHub 私有仓库。
- 服务器环境：安装 `php-pdo`（pdo_sqlite）、`php-mbstring`、`php-fpm` 扩展（PHP 8.0.30）。
- 补全产品需求（docs/01）、商业模式与分账规则（docs/02）、技术架构（docs/03）、数据库（docs/04）、接口（docs/05）、规划（docs/06）。
- 后端零依赖微框架：Router（带角色权限）、Request（参数校验、元转分）、Auth（token 会话）、Db（SQLite、可嵌套事务、类型还原）。
- 定价引擎 `PricingService`：代金券模式 / 平台定价模式，"至少比竞品便宜 1 元"校验，经理佣金向下取整到分。
- 订单 `OrderService`：下单快照、模拟支付、12 位券码、逐张核销结算、外卖固定时间点（截单自动顺延次日）、退款回补库存、分账流水。
- 业务接口：学校、首页、跑腿/代取快递、二手、树洞、本地生活、订单、商家端、客户经理端、AI 问答（FAQ 兜底 + OpenAI 兼容接口预留）。
- 演示数据：试点学校 + 3 所筹备中学校、6 家已入驻商家 + 1 家待审核、10 个商品、跑腿/二手/树洞/FAQ、演示订单与流水。
- 测试：`php tests/run.php`，14 项定价单元测试 + 42 项接口集成测试，**全部通过**。

**决策**
- 金额全程以「分」存储计算；接口入参为元、出参为分。
- 订单金额快照 = 单份金额 × 数量，保证按张核销时可整除拆账。
- 不改动服务器现有 Nginx 站点，原型用 PHP 内置服务器（systemd 托管）在 8100 端口预览。
- 对学生接口隐藏商家结算价、券成本、平台/经理收入等商业字段。

**踩坑**
- PHP 8.0 的 pdo_sqlite 把整数返回成字符串 → `Db::typed()` 按 `getColumnMeta` 的存储类型还原。
- `escapeshellarg` 在 C locale 下会丢弃中文路径字符（项目路径含"小程序"）→ 测试中设置 `LC_CTYPE=C.UTF-8`。

**遗留**
- H5 原型页面与手机框预览页（下一步）。
- 文档 06 中"待确认事项"需产品方确认。
